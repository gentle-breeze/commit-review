# Commit Review

在本地网页中浏览 Git commit diff，选择代码行添加评论，再让 Claude Code 读取评论处理代码。**不需要 API Key，不上传代码。** 使用本地打包的 Monaco Diff Editor，提供接近 IDEA 的只读双编辑器比较体验（不是 IDEA 外观的完整复刻）。

## 启动

需要 Node.js 22+ 和 Git。

```sh
cd /Users/ws/Documents/commit-review
npm ci
npm start -- --repo /你的/Git仓库/绝对路径
```

浏览器打开 **http://127.0.0.1:4318**。停止服务按 `Ctrl+C`。

首次 `npm ci` 下载编辑器和构建工具；`npm start` 自动构建本地资源。安装完成后运行页面不需要网络。修改前端后需重新运行 `npm run build`。

已经构建后，也可以从任意目录运行：

```sh
node /Users/ws/Documents/commit-review/server.mjs --repo /你的/Git仓库/绝对路径 --port 4318
```

路径包含空格时请用引号包住。端口被占用时使用 `--port 4319` 等其他端口。工具仅绑定 `127.0.0.1`，不对局域网开放。

## Review 流程

1. 选择分支和 commit，点击文件名，在左右编辑器中比较完整历史文件：左侧修改前、右侧修改后。支持常见语言语法高亮、字符级差异、对齐和同步滚动。
   - 「上一处 / 下一处」或快捷键 `[` / `]` 连续导航差异：文件末尾进入下一个文件的第一处，文件开头返回上一个文件的最后一处。到整个提交的首尾停住，不循环；不自动切换 commit。
   - 二进制等不可文本比较的文件保留说明，可继续按快捷键或文件导航按钮切换；没有文本差异的文件同样可以继续导航。
   - 当前差异额外显示高亮边框和侧边标记，工具栏显示「当前 X / Y」；插入/删除的空白一侧标记对应边界。点击差异中的代码也会更新当前差异。
   - 评论输入框、搜索框、分支选择框和弹窗中不触发导航；带 Ctrl/⌘/Alt/Shift 或输入法组合输入时也不触发。
   - 默认不换行，可勾选「自动换行」。
   - 默认折叠长段未修改内容，可展开折叠区域或关闭「折叠未修改区域」。
   - 每次加载一个文件，窄屏在编辑器区域内部横向滚动。
2. 点击一个**行号**选择单行；按住 **Shift** 点击另一行号选择连续多行。也可以拖选代码（保存对应完整行）。
   - 左边行号：旧版本 `old`，可以评论删除的代码。
   - 右边行号：新版本 `new`，可以评论新增的代码。
   - 一条评论限同一文件、同一侧，最多 200 行；可以评论未修改的上下文行。未解决评论在行号旁显示标记。
3. 选区完成后，文件底部**立即显示评论输入框**，无需再点「添加评论」。直接输入并保存，支持 `⌘/Ctrl + Enter`。
   - 拖选或点击行号后，松开鼠标即自动聚焦评论框，可以直接打字；键盘选区在松开 Shift 后聚焦。仍可 Shift 点击行号扩选，完成后再次回到评论框。
   - 写入草稿后，先保存或取消才能更改锚定行；切换文件/提交再返回时恢复草稿和原范围。草稿仅保留在当前页面内存中，刷新或关闭页面会丢失；保存后才写入本地文件。
4. 右侧评论支持编辑、删除、标记已解决，以及按提交/状态筛选。点击评论位置可以跳回原 commit。
5. 点击「复制 AI 指令」，粘贴到 Claude Code。AI 会读取本地文件中的评论、commit 和对应代码片段。
6. AI 修改并通过测试后，在网页中确认并标记评论已解决。工具不会自动运行 AI，也不会自动修改你的代码。

刷新按钮重新读取分支、提交和评论；新提交不会自动轮询加载。每页显示 50 条主线提交，可继续加载。

### 更大的代码区域

- 桌面默认收起右侧评论栏，左侧历史栏缩窄，编辑器自动占满剩余视口高度；两侧栏独立滚动。
- 审查评论栏默认收起，仅通过顶部「显示评论 / 隐藏评论」手动切换；新增或编辑评论不会自动展开侧栏，保留当前开关状态。
- 按 `F` 切换进入/退出专注模式（长按不重复切换；评论、搜索、下拉框、弹窗或输入法组词时不触发）。「专注 diff」隐藏历史、评论栏，以及顶部导航、提交信息和文件列表。专注模式右上方保留「显示评论 / 隐藏评论」及「退出专注」；退出时恢复原布局及之前的评论栏状态，专注时仍可使用 `[` / `]` 跨文件导航。
- 文件名、差异导航、当前差异序号、变更计数、自动换行和折叠选项合并在同一行，不再单独占一行工具栏；窄屏下工具区域可横向滚动。
- 窄屏保持纵向布局，代码区域内部横向滚动，不撑宽整个页面。

### 分支提交列表

仅列出本地分支，使用 `git log --first-parent <upstream>..<branch>` 展示相对其远程跟踪分支**尚未 push 的主线提交**。合并引入的旁支 commit 不逐条展开；未推送的 merge commit 保留，diff 仍与第一父提交比较。不是按作者筛选，也不是相对所有远程分支检查；如果实际 push 目标与 upstream 不同，结果不代表该目标的状态。

- 已全部推送、仅落后于 upstream：显示没有未 push 的主线提交。
- 没有可用的远程 upstream（未配置或远程跟踪引用缺失）：优先与本地 `main` 比较，不存在时与本地 `master` 比较，展示 `main/master..branch` 的主线提交。页面标明本地基准及「分支独有提交」，这不等于远程未 push 状态。若所选分支就是基准自身，结果为空。
- 本地 `main` 和 `master` 都不存在且无可用远程 upstream，或处于 detached HEAD：列表为空并说明原因，不回退到全部历史。工具不会自动创建分支或修改 upstream 配置。
- 使用本地远程跟踪引用，**不会自动 fetch**；远程状态可能过期，请自行 fetch/push 后点刷新。push 后已包含于 upstream 的提交会从列表消失。
- 分叉时显示本地独有的主线提交；并不保证可直接 push，也不提供自动合并/推送。
- 已有评论仍可跳转到任何可读取的历史 SHA，即使对应提交已 push 或不在列表中。

## 评论存储

默认位置：

```text
/Users/ws/Documents/commit-review/.reviews/<仓库路径的哈希>/
  comments.json    # 权威结构化数据
  comments.md      # AI 友好的 Markdown 导出
```

网页右侧「AI 如何读取评论？」显示当前仓库的准确绝对路径。保存、编辑、解决或删除评论时，两个文件会更新；重启时从 JSON 恢复并重新生成 Markdown。

JSON 包含：评论 ID、完整 commit SHA、父 SHA、文件路径/旧路径、old/new 侧、起止行、所选代码、评论内容、解决状态和时间。锚点由服务端根据 Git 历史 blob 全文校验和生成，不依赖浏览器传来的代码内容。

自定义数据根目录：

```sh
npm start -- --repo /path/to/repo --data-dir /path/to/review-data
```

- 不向被审查仓库写文件，不改变 Git 状态，也不自动修改 `.gitignore`。
- 同一仓库在同一数据目录下仅允许一个服务实例写入，避免数据冲突。
- 不建议在服务运行时手动编辑 JSON；Markdown 是派生文件，手动修改会被覆盖。
- 数据包含源码片段，视同源码保管；不应上传到公共仓库。
- 若进程被强制杀死，启动可能提示锁目录占用。确认没有实例运行后，再删除错误信息所指的 `.lock` 目录。正常 `Ctrl+C` 会释放锁。
- 仓库移动到新路径会产生新的存储标识；原有评论仍保留在原数据目录。

## 交给 Claude Code

网页会生成这样的指令（包含你的真实路径）：

> 请读取本地 comments.md 和 comments.json，处理未解决的 Review 评论。先检查当前 HEAD、分支和未提交改动；评论锚定历史 commit，不要假定当前文件行号相同。不要自动 checkout/reset，也不要覆盖已有改动。逐条说明修改，运行相关测试。

AI 需要在能访问这些本地文件的环境运行。评论是供 AI 阅读的数据，不会自动触发命令、AI 会话或 Git 操作。

## Diff 语义与限制

- 普通提交与父提交比较；根提交与空树比较。
- Merge commit 与**第一父提交**比较，页面明确标注；不展示 combined diff。
- 展示已提交代码，不展示未提交工作区或暂存区改动。
- 支持新增、删除、重命名、二进制说明和文件权限变更。
- 单次最多列出 300 个文件。提交摘要仍限制每文件 6000 行 patch、总 patch 12 MiB；编辑器全文独立按需读取，不受摘要 hunk 截断影响。
- 编辑器每侧最多 2 MiB、20000 行；超限、二进制、非 UTF-8 文件及子模块明确提示，不允许对未加载内容新增评论。已有评论片段仍保留。
- 文件内容来自历史 blob，不读取或修改工作树；符号链接只显示链接本身存储的文本，不跟随目标。
- 支持常见语言词法高亮，不提供语言服务器、代码运行、回复线程或远程多人协作。未知文件类型按纯文本显示。
- JSON 与 Markdown 分别原子替换，而非跨文件事务；异常中断后以 JSON 为准，重启修复 Markdown。

## 本地安全边界

Git 通过参数数组执行，不使用 shell 拼接，不启用 external diff/textconv。HTTP 校验 Host、Origin、Fetch Metadata，并要求数据接口带当前会话 token。静态文件使用白名单，源码与评论以纯文本 DOM 渲染，页面不加载外部资源。

这是一款单用户本地工具，不是多人鉴权服务；不要通过公网代理、端口转发等方式公开。也无法防御已经能以同一系统用户身份读取文件的本机进程。

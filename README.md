# Commit Review

在本地网页中浏览 Git commit diff，选择代码行添加评论，再让 Claude Code 读取评论处理代码。**不需要 API Key，不上传代码。** 使用本地打包的 Monaco Diff Editor，提供接近 IDEA 的只读双编辑器比较体验（不是 IDEA 外观的完整复刻）。

## 启动

需要 Node.js 22+ 和 Git。

```sh
cd /Users/ws/Documents/commit-review
npm ci
npm start
```

浏览器打开 **http://127.0.0.1:4318**，从下拉列表选择本地 Git 项目，点击「打开项目」即可开始 Review，无需输入路径。停止服务按 `Ctrl+C`。

默认查找工具所在目录的父目录（本项目为 `/Users/ws/Documents`）自身及直接子目录中的 Git 工作区，不递归扫描。非 Git 目录自动忽略，支持 linked worktree，重复路径合并。点击顶部「刷新」可更新项目列表；没有项目时会显示说明并禁用打开按钮。项目打开失败时可重试或选择其他项目。

其他目录的项目可指定项目目录：

```sh
npm start -- --projects-dir /你的/项目目录
```

也可以在启动时直接指定项目，跳过网页选择：

```sh
npm start -- --repo /你的/Git仓库/绝对路径
```

`--repo` 是可选参数；未指定时不会自动审查当前目录。同一个服务和端口支持同时审查多个项目。顶部「新标签页选项目」可打开另一个独立项目；「切换项目」更换当前标签页。项目规范化路径保存在标签页 URL 的 `repo` 参数中，刷新后恢复同一项目，其他标签页不受影响。`--repo` 指定根地址的默认项目，仍可打开其他项目。不同项目的评论、锁、diff 缓存和隐藏偏好按仓库隔离；同一项目的多个标签页共享已保存评论及隐藏偏好，选择与未保存草稿各自独立。切换或关闭含未保存草稿的页面时，浏览器会提示确认。

首次 `npm ci` 下载编辑器和构建工具；`npm start` 自动构建本地资源。安装完成后运行页面不需要网络。修改前端后需重新运行 `npm run build`。

已经构建后，也可以从任意目录运行：

```sh
node /Users/ws/Documents/commit-review/server.mjs --port 4318
# 或直接打开指定项目：
node /Users/ws/Documents/commit-review/server.mjs --repo /你的/Git仓库/绝对路径 --port 4318
```

路径包含空格时请用引号包住。端口被占用时使用 `--port 4319` 等其他端口。工具仅绑定 `127.0.0.1`，不对局域网开放。

## Review 流程

1. 选择分支和 commit，点击文件名，在左右编辑器中比较完整历史文件：左侧修改前、右侧修改后。支持常见语言语法高亮、字符级差异、对齐和同步滚动。
   - 「上一处 / 下一处」或快捷键 `[` / `]` 连续导航差异：文件末尾进入下一个文件的第一处，文件开头返回上一个文件的最后一处。到提交末尾继续「下一处」或 `]`，会按作者时间从旧到新进入下一个可见提交；正常列表跳过隐藏项，查看隐藏项时遵循该列表。首次跨提交前补齐当前审查范围的分页，到时间最新的可见提交明确提示，不循环。「上一处」在提交开头按时间从新到旧进入前一个可见提交的最后一个可见文件、最后一处差异；到时间最早的可见提交提示，不循环。空提交或过滤后无文件时提供双向继续按钮；二进制或无文本差异文件保留说明并可继续，不静默跳过审查内容。评论关联的列表外提交没有确定的后继，会提示先选择列表中的起点。
   - 二进制等不可文本比较的文件保留说明，可继续按快捷键或文件导航按钮切换；没有文本差异的文件同样可以继续导航。
   - 当前差异额外显示高亮边框和侧边标记，工具栏显示「当前 X / Y」；插入/删除的空白一侧标记对应边界。点击差异中的代码也会更新当前差异。
   - 评论输入框、搜索框、分支选择框和弹窗中不触发导航；带 Ctrl/⌘/Alt/Shift 或输入法组合输入时也不触发。
   - 默认不换行，可勾选「自动换行」。
   - 代码区或其工具栏聚焦时，按 `⌘/Ctrl + +`（也支持 `=`）放大代码字号、`⌘/Ctrl + -` 缩小、`⌘/Ctrl + 0` 恢复默认 17px；也可点击工具栏 `A− / 当前字号 / A+`。每次调整 1px，范围 10–24px，两栏同步。字号在当前页面切换文件/提交时保留，刷新后恢复默认，与换行等选项一样不持久化。评论输入框、编辑器搜索框、弹窗及代码区外不接管这些按键，保留原生行为；仅调整代码字号，不缩放整个页面。
   - 默认折叠长段未修改内容，可展开折叠区域或关闭「折叠未修改区域」。
   - 每次加载一个文件，窄屏在编辑器区域内部横向滚动。
2. **拖选代码或使用键盘选择**，评论精确绑定选中的字符内容，支持同一行的一部分和跨行选区。选区使用明显的背景与边框，输入评论时仍保持高亮。点击一个**行号**仍选择整行；按住 **Shift** 点击另一行号选择连续多行。
   - 左边行号：旧版本 `old`，可以评论删除的代码。
   - 右边行号：新版本 `new`，可以评论新增的代码。
   - 一条评论限同一文件、同一侧，最多 200 行；可以评论未修改的上下文行。已评论代码显示下划线和行号旁标记；已解决评论使用较淡的虚线下划线。空行保留行号旁标记。
   - 单击带下划线的代码，在附近显示已有评论；点击处命中的多条评论会一起展示，同一行的其他字符不会触发不相关的精确选区评论，新旧版本分别匹配，不受侧栏筛选影响。点击框外或「关闭」收起，不自动展开侧栏。拖选代码及点击行号仍用于新增评论；查看已有评论不会丢弃未保存草稿。
3. 选区完成后，代码附近**立即显示浮动评论框**，不占用 diff 底部空间，无需再点「添加评论」。优先显示在选区下方，空间不足时移到上方；滚动及调整窗口后会跟随定位，选区离开视口时贴近可见边界。直接输入并保存，支持 `⌘/Ctrl + Enter`。
   - 拖选或点击行号后，松开鼠标即自动聚焦评论框，可以直接打字；键盘选区在松开 Shift 后聚焦。仍可 Shift 点击行号扩选，完成后再次回到评论框。
   - 评论框为空时，按 `⌘/Ctrl + C` 复制刚划选的代码：拖选保留精确字符范围，点击行号则复制对应整行。评论框已有内容时保留原生评论文本复制行为，不覆盖剪贴板。
   - 点击评论框外任意位置收起浮框，点击框内可继续输入。收起不会丢弃草稿；再次划选代码或点击行号可重新打开。
   - 写入草稿后，先保存或取消才能更改锚定行；再次选择时恢复原草稿和原范围，不会把已有评论移到其他行。切换文件/提交再返回时保留草稿；已收起的浮框不会自动弹出。草稿仅保留在当前页面内存中，刷新或关闭页面会丢失；保存后才写入本地文件。
4. 右侧评论支持编辑、删除、标记已解决，以及按提交/状态筛选。点击评论正文或位置链接可跳回原 commit 和划线位置，并显示持续的选区高亮、下划线及侧边标记（已解决评论也支持）。新拖选评论保存精确的起止行列及所选片段，位置采用 1 起始 UTF-16 列，结束位置不包含在内，换行统一 LF。旧评论没有列坐标时继续按整行恢复，不猜测或修改历史范围；行号评论也保持整行语义。JSON 与 AI Markdown 均保留对应位置及片段。
5. 点击「复制 AI 指令」，粘贴到 Claude Code。AI 会读取本地文件中的评论、commit 和对应代码片段。
6. 使用 `review-comments` Skill 时，AI 仅追加回复说明分析/修改/测试结果，不关闭或重新打开评论。用户确认后在网页中手动标记已解决，也可继续追问、回复或重新打开讨论；工具本身不会自动运行 AI，也不会自动修改你的代码。

### 回复与已解决筛选

- 「下一条评论」按钮或 `Alt/Option + J` 按当前评论范围、状态和隐藏模式下的列表顺序导航，自动定位跨文件/提交的代码并显示评论栏；未选评论时从第一条开始，末尾停止、不循环。输入框、搜索框、下拉框、弹窗、输入法组合输入和长按不触发；当前评论有非空草稿时先保存或取消，草稿不丢失。选择「全部提交」可跨提交导航；没有评论时按钮禁用。点击评论定位代码时，左侧同步选中并滚动到对应提交；不在当前已加载或搜索列表中的历史提交单独标注为「评论关联提交」，不改变分支或搜索条件，不计入全选范围，也不恢复隐藏提交。
- 未解决评论显示「未读 / 已读」及未读总数。点击评论定位、打开编辑/回复窗口、点击代码标记打开评论浮框，或主动展开回复时视为查看；仅渲染列表、轮询或程序恢复展开状态不算已读。新回复、正文变化或重新打开讨论后变为未读，即使此前已查看；自己刚发送的回复视为已读。已解决评论不显示已读标记。状态仅存在本页面内存，整页刷新/重新打开后重置；顶部刷新、自动拉取、筛选、隐藏恢复和重渲染保留同一版本的已读状态，不写服务端。

- 评论卡片和代码旁浮框中的回复默认展开，点击「N 条回复 · 收起」可折叠，再次点击「展开」查看；键盘 Tab 聚焦后可用 Enter/空格操作。展开状态按评论与展示位置保存在当前标签页会话中，刷新、轮询或切换筛选不重置；浏览器存储不可用时仍可切换，但只在当前页面保留。回复窗口默认展开历史，收起历史不会清空输入草稿；长线程可独立滚动，无回复时不显示折叠入口。
- 桌面右侧评论面板左边界可拖动调宽；边界获得焦点后用左右方向键调整（每次 10px，Shift 为 40px），Home/End 到最小/最大，双击恢复默认 290px。宽度至少 260px、最多 640px，并随可用空间收紧，优先保留代码区。拖动时按 Escape 取消。宽度仅在当前页面保留，刷新恢复默认；窗口不宽于 1100px 时面板移到下方并隐藏拖动条，恢复宽窗口后恢复可用范围内的偏好宽度。

- 侧栏评论卡片或代码下划线浮框中的「回复」打开讨论窗口，支持多次回复及 `⌘/Ctrl + Enter` 发送。用户与 AI 回复按保存顺序显示，带来源和时间，原评论与代码锚点不变。
- 「显示评论」后，可将状态下拉框设为「已解决」，只查看已解决讨论及完整回复；「全部提交」可查看不在当前 commit 中的评论。
- 回复不会自动重新打开已解决评论；需要继续处理时点击「重新打开」。状态记录最近操作者（用户/AI）和时间；旧评论无来源时不推测。
- 评论每 5 秒同步一次，外部 AI 回复和状态会自动出现。回复/编辑弹窗打开、评论保存中及页面在后台时暂停同步，避免覆盖输入；仍可手动刷新。取消回复或刷新/关闭网页会丢失尚未发送的回复。

左侧 commit 列表保持标题、短 SHA、作者和时间的紧凑布局。鼠标悬停或键盘聚焦某条提交时，浮框显示完整标题与正文（保留换行）；正文为空时明确提示。鼠标可移入浮框滚动长正文，移开、按 Escape 或点击提交后收起；点击提交仍加载 diff。

提交左侧复选框可多选，再点「隐藏所选」只保留关注项。勾选不会打开提交；「全选当前已加载列表」只选择当前搜索与显示模式下已加载的行，加载更多不会自动勾选新增行。可搜索标题、作者或 SHA；搜索仅覆盖已加载提交。

「本仓库已隐藏 N 条」统计整个仓库保存的隐藏 SHA（包括其他分支或当前未加载项）。「查看隐藏项」在当前分支和搜索范围内查看、勾选恢复；「恢复全部」恢复本仓库全部隐藏项。隐藏当前提交后自动选择当前列表第一条，全部隐藏时显示空状态，仍可查看隐藏项或加载更多。隐藏偏好按仓库路径和完整 SHA 存在当前浏览器 localStorage，同一仓库各分支共享、不同仓库隔离，刷新后保留；换浏览器、端口或清除网站数据不会共享偏好。存储不可用时提示并仅保留当前页面。隐藏只是列表过滤，不改 Git 提交、评论及其状态；隐藏同时过滤正常视图中的关联评论、回复、计数、评论导航和代码标记，已打开的关联浮框也会关闭；「查看隐藏项」单独显示隐藏提交及其讨论，恢复提交后在关注列表恢复内容。仅过滤显示，不改服务端数据。编辑器搜索与差异快捷键保持原行为。

刷新按钮重新读取分支、提交和评论；新提交不会自动轮询加载。每页显示 50 条主线提交，可继续加载。

### 跳过 Test 文件

代码区上方的「跳过 *Test 文件」同时控制文件列表和上下处导航，在专注模式也可切换。按文件 basename 去掉最后一个扩展名后是否以 `Test` 结尾匹配，区分大小写：`FooTest.java`、`FooTest` 会跳过，`TestHelper.java`、`FooTestHelper.js`、`Test/Foo.java`、`Footest.java` 不跳过。重命名按新文件名判断，删除按原文件名判断；只去掉最后一个扩展名，因此 `FooTest.spec.ts` 不匹配。

默认关闭；开关按规范化仓库路径保存到当前浏览器，不同项目隔离，整页刷新保留。关闭开关即可恢复；不修改 Git 文件或删除评论，已有草稿保留在页面内存。被跳过文件的评论仍可阅读/回复，定位时提示先关闭开关。

### 更大的代码区域

- 桌面默认收起右侧评论栏，左侧历史栏缩窄，编辑器自动占满剩余视口高度；两侧栏独立滚动。
- 审查评论栏默认收起，仅通过顶部「显示评论 / 隐藏评论」手动切换；新增或编辑评论不会自动展开侧栏，保留当前开关状态。
- 按物理 `F` 键切换进入/退出专注模式（长按不重复切换；评论、搜索、下拉框、弹窗或输入法组词时不触发）。按物理按键识别，中英文布局下非编辑区可使用；实际 composition、输入框和可编辑内容仍保留输入行为。「专注 diff」隐藏历史、评论栏，以及顶部导航、提交信息和文件列表。专注模式顶部保留当前提交短 SHA 和标题，以及「显示评论 / 隐藏评论」及「退出专注」。悬停、Tab 聚焦或点击提交标题可查看完整 SHA、作者、时间和提交正文；长说明可滚动，聚焦标题时方向键/PageUp/PageDown/Home/End 可滚动说明，Escape 或点击外部关闭；退出时恢复原布局及之前的评论栏状态，专注时仍可使用 `[` / `]` 跨文件导航。
- 文件名、差异导航、当前差异序号、变更计数、自动换行和折叠选项合并在同一行，不再单独占一行工具栏；窄屏下工具区域可横向滚动。
- 窄屏保持纵向布局，代码区域内部横向滚动，不撑宽整个页面。

### 分支提交列表

仅列出本地分支，使用 `git log --first-parent <upstream>..<branch>` 展示相对其远程跟踪分支**尚未 push 的主线提交**。合并引入的旁支 commit 不逐条展开；未推送的 merge commit 保留，diff 仍与第一父提交比较。跨提交导航使用列表显示的 Git 作者时间（`%aI`）按旧到新排序，同一时刻按第一父链从旧到新稳定处理；它独立于列表的原有倒序展示。作者时间可能不随 Git 遍历顺序递增，因此跨提交前补齐当前范围的提交分页，仍遵守隐藏、搜索和 Test 过滤，不跨出当前分支审查范围；加载期间范围变化会提示刷新。不是按作者筛选，也不是相对所有远程分支检查；如果实际 push 目标与 upstream 不同，结果不代表该目标的状态。

- 已全部推送、仅落后于 upstream：显示没有未 push 的主线提交。
- 没有可用的远程 upstream（未配置或远程跟踪引用缺失）：优先与本地 `main` 比较，不存在时与本地 `master` 比较，展示 `main/master..branch` 的主线提交。页面标明本地基准及「分支独有提交」，这不等于远程未 push 状态。若所选分支就是基准自身，结果为空。
- 本地 `main` 和 `master` 都不存在且无可用远程 upstream，或处于 detached HEAD：列表为空并说明原因，不回退到全部历史。工具不会自动创建分支或修改 upstream 配置。
- 使用本地远程跟踪引用，**不会自动 fetch**；远程状态可能过期，请自行 fetch/push 后点刷新。push 后已包含于 upstream 的提交会从列表消失。
- 分叉时显示本地独有的主线提交；并不保证可直接 push，也不提供自动合并/推送。
- 已有评论仍可跳转到任何可读取的历史 SHA，即使对应提交已 push 或不在列表中。

### 多项目 API 上下文

`GET /api/info` 返回默认项目或选择入口信息，不改变服务器当前项目。`POST /api/repository` 接收绝对仓库路径，返回规范化的 `repository`、`projectId` 和 `token`。后续项目 API 请求同时发送 `X-Review-Project` 和 `X-Review-Token`；错误组合会被拒绝，不会写入其他项目。选择项目的管理请求使用入口令牌或已有项目凭据。同一规范化路径（包括符号链接）复用会话。

兼容旧客户端：使用 `--repo` 时，不带项目标识的请求始终指向固定默认项目；无默认项目且仅打开一个项目时可使用旧方式。打开多个项目后，无标识的项目数据请求会被拒绝，客户端必须显式指定项目。项目会话和锁保留到服务停止；无效 URL 路径显示项目选择错误，不回退到另一项目。URL 含本地路径，请勿把它作为公开链接分享。

## 交给 Claude Code

网页会生成这样的指令（包含你的真实路径）：

> 请读取本地 comments.md 和 comments.json，处理未解决的 Review 评论。先检查当前 HEAD、分支和未提交改动；评论锚定历史 commit，不要假定当前文件行号相同。保护已有改动，按独立功能或业务语义安排本地提交，不以数量多少为目标；使用简洁标题，在正文说明具体事项及必要背景，不套固定模板；整理未共享历史前保留恢复引用，不擅自改写共享历史或推送。逐条说明修改，运行相关测试。

AI 需要在能访问这些本地文件的环境运行。评论是供 AI 阅读的数据，不会自动触发命令、AI 会话或 Git 操作。

### Claude Code Skill：review-comments

项目内已提供 `.claude/skills/review-comments/SKILL.md`，复用下面的 AI CLI，不需要 API Key，也不直接编辑评论数据。它仅在显式调用时执行，默认读取目标项目的未解决评论及完整讨论，核对历史与当前代码。正常调用即允许在指定范围、项目指令及当前权限内修复真实且需要解决的问题并验证，无需为每个正常修复另行询问；处理后必须向对应评论追加回复，说明结果或未处理原因。明确要求“只分析”“只回复”时不改代码，仅查看或总结时不写回复。Skill 不改变评论状态，关闭或重新打开均由人处理。

在 `commit-review` 项目目录中启动 Claude Code 后调用：

```text
/review-comments
```

无参数时目标是 Claude Code 当前工作目录的 Git 项目。要审查其他项目，请显式指定目标仓库根目录：

```text
/review-comments --repo /absolute/path/to/target-repo
/review-comments --repo /absolute/path/to/target-repo --url http://127.0.0.1:4319
/review-comments --repo /absolute/path/to/target-repo --comment 评论UUID
/review-comments --repo /absolute/path/to/target-repo 只分析，不修改代码
```

- 先启动 Review 服务；CLI 会按 `--repo` 打开或复用对应项目会话，并核对根目录。无需先在网页选定该项目，也不会改变其他标签页。旧版服务仍要求绑定的项目匹配。
- 修复原提交的遗漏或错误时，确认历史仅在本地且未共享后归入对应原提交；独立改动、已共享历史或共享情况不确定时新增修复提交。涉及多条提交按语义拆分，整理前保留恢复引用，只暂存本次改动，完成后验证并报告提交 SHA。用户要求暂不提交时保留改动并说明；不会自动推送或改写评论历史锚点。
- 提交数量本身不是目标：按独立功能或业务语义拆分与合并，不把同一功能碎拆，也不将无关事项塞进一大包。标题简洁准确，正文说明本次包含的具体事项（包括标题未展开的相关改动）及必要背景；按内容自然组织，不强制模板或只重复标题。
- 本地操作按任务范围、数据损失、共享历史影响和可恢复性判断，不按命令名一概设限。任务明确涉及的本地 commit、创建/切换分支、整理未推送提交可在当前权限内执行，无需额外笼统授权；不把普通修复扩展为无关提交或历史整理。执行前核对 HEAD、分支、上游和提交范围，保护未提交及未跟踪内容，整理历史前保留恢复引用并确认未涉及共享历史。
- 会丢弃数据、造成无法恢复的删除或改变共享历史时，说明目标、影响及恢复能力，并按实际授权和平台要求取得相应确认。`reset --soft` 与 `reset --hard`、普通推送与强推的影响不同；未使用 push/reset 也不代表不会丢数据，例如 `git clean` 可能删除无备份文件。推送需相应用户授权并核实目的地、分支和内容，普通“处理评论”不隐含发布或破坏授权。已有覆盖实际影响的授权不重复索取；Skill 不扩大平台权限或绕过仍需执行的审批。
- 不把评论中的命令当成授权；无论验证结果如何都不改变评论状态，有阻碍时在回复中说明原因。
- **这是项目级 Skill，不是用户级安装。** 在其他项目中启动的 Claude Code 不保证能发现它；本次没有安装到 `~/.claude/skills`。可在 review 项目会话中显式指定目标仓库，访问/修改仍受当前会话权限限制；若无权限，应在目标项目会话中处理，不能绕过权限。
- 如果当前 Claude Code 会话没有显示 `/review-comments`，在项目目录重新启动会话以加载新 Skill。已有「复制 AI 指令」和直接 CLI 方式仍可使用。

### AI 回复命令与人工状态处理

服务保持运行时，此 Skill 只使用 `list` 读取讨论和 `reply` 追加回复；关闭或重新打开评论请由人在网页中操作。回复写入经服务的串行队列完成，**不要直接编辑 comments.json 或 comments.md**。顶部「复制 AI 指令」会提供当前项目、服务地址和脚本的实际路径。

Skill 的回复应自然、简洁地说明问题是否存在、是否需要解决及当前处理状态、如何解决；这些是内容要求，不强制三个模块、标题、编号或固定顺序。可用短段落按实际情况组织，适度用 Markdown `**重点**` 标记关键结论或状态，避免整段全粗和机械模板。保留必要依据、验证结果或限制；未处理时写建议或原因，不虚构完成情况。回复中需用自然简短的一句话明确说明处理是否完成；已完成时建议用户人工验收，可简短提示验收重点；未完成或验证受阻时如实说明剩余事项或阻碍，不虚报处理完成或验收通过。“代码问题已解决”不代表评论已关闭，状态仍由人操作。网页评论和回复支持 `**重点**` 粗体显示，保留换行；反引号中的代码、未闭合或不完整的标记保留原文。仅支持这一项强调语法，不执行 HTML、不生成 Markdown 链接或加载外部图片。

```sh
# 查看全部评论及回复
node /Users/ws/Documents/commit-review/ai-review.mjs list --repo /path/to/repo

# 回复，不覆盖用户原文
node /Users/ws/Documents/commit-review/ai-review.mjs reply --repo /path/to/repo --comment 评论UUID --body '**目前还不能确认这个问题是否存在**，缺少触发问题的输入，是否需要修改仍待判断。我还没有改动代码，建议先补充复现输入，再验证是否需要修复。'
```

- 默认连接 `http://127.0.0.1:4318`，其他端口使用 `--url http://127.0.0.1:4319`。只接受本地 HTTP 地址，不跟随重定向。
- `--repo` 必须是目标 Git 工作区根目录。多项目服务为它提供独立项目标识及令牌，后续读取和写入均携带两者；无效路径、根目录核对失败或服务未运行时返回错误。旧版单项目服务继续要求路径匹配。
- 多行内容可用 `--body-file /path/to/utf8.txt` 替代 `--body`；两者不能同时使用。reply 正文必填。
- AI 如实回复处理和验证结果，是否关闭由人判断。底层 CLI/API 的 `resolve` / `reopen` 能力仍保留，但不属于此 Skill 的可执行操作；本次规则调整不改变网页的人工状态操作。
- 「AI」仅是操作来源标签，不是模型身份认证。它不调用模型、不需要 API Key；有本机服务访问权限的进程可以调用该接口。
- JSON version 1 向后兼容。回复保存在可选 `replies` 数组中（ID、author、body、createdAt），状态来源/时间为可选 `resolvedBy` / `resolvedAt`。旧评论没有这些字段仍可正常展示。Markdown 包含全部回复。

## Diff 语义与限制

- 普通提交与父提交比较；根提交与空树比较。
- Merge commit 与**第一父提交**比较，页面明确标注；不展示 combined diff。
- 展示已提交代码，不展示未提交工作区或暂存区改动。
- 支持新增、删除、重命名、二进制说明和文件权限变更。
- 单次最多列出 300 个文件。提交摘要仍限制每文件 6000 行 patch、总 patch 12 MiB；编辑器全文独立按需读取，不受摘要 hunk 截断影响。
- 编辑器每侧最多 2 MiB、20000 行；超限、二进制、非 UTF-8 文件及子模块明确提示，不允许对未加载内容新增评论。已有评论片段仍保留。
- 文件内容来自历史 blob，不读取或修改工作树；符号链接只显示链接本身存储的文本，不跟随目标。
- 支持常见语言词法高亮，不提供语言服务器、代码运行或远程多人协作。未知文件类型按纯文本显示。
- JSON 与 Markdown 分别原子替换，而非跨文件事务；异常中断后以 JSON 为准，重启修复 Markdown。

## 本地安全边界

Git 通过参数数组执行，不使用 shell 拼接，不启用 external diff/textconv。HTTP 校验 Host、Origin、Fetch Metadata，并要求数据接口带当前会话 token。静态文件使用白名单，源码与评论以纯文本 DOM 渲染，页面不加载外部资源。

这是一款单用户本地工具，不是多人鉴权服务；不要通过公网代理、端口转发等方式公开。也无法防御已经能以同一系统用户身份读取文件的本机进程。

### 按文件看提交

点击文件工具栏「按文件看提交」，按完整相对路径查找文件，再查看它在当前审查范围内的提交、增删行数、重命名、diff 和关联评论。索引覆盖选定分支的完整审查范围（与提交列表相同的上游或 main/master 比较规则，沿第一父提交），不限于左侧已加载的 50 条。打开索引时固定基准与 HEAD 快照；刷新索引可获取新提交。

隐藏提交模式和「跳过 Test 文件」同样适用；左侧提交标题/作者搜索不参与文件索引，弹窗提供独立路径搜索。只有 Git 识别出的重命名才连接历史，不按文件名猜测；删除后同路径重建独立列出。二进制改动显示说明而不伪造行数。评论按项目、提交和文件精确关联。

索引每页扫描最多 25 条提交，最多支持 5000 条提交、单提交 10000 个文件、总计 100000 条文件改动；达到限制或读取失败时明确显示「索引未完成」，不将部分结果当完整结果。文件列表与单文件历史分批显示。普通提交 diff 最多显示 300 个文件，但从索引打开其后的文件会进入明确标记的单文件视图，仍支持历史内容与评论。切换分支/项目或关闭弹窗会丢弃迟到的索引响应。服务端快照保留至多 10 分钟，过期后重新刷新。


### 提交重写后的评论关联与复核

amend、rebase、squash 或 split 后，旧评论仍保留原始 SHA、路径、选区、代码片段及讨论。先在评论栏选择「全部提交」找到原评论，点击「关联 / 对照」，填写后续提交或分支并预览。服务解析为固定 SHA，尝试原路径与 Git 重命名线索；显示文本匹配的候选位置，无匹配时仅提供路径和原行号附近的参考。多个匹配均需人工选择，也可指定路径和行号纠正。跨多个新提交拆分时，重复添加多个关联；多条旧评论也可分别关联同一个 squash 提交。

确认前对照原始片段和新版本代码。**候选不是提交身份映射，关联、SHA 改变和代码相似度都不是问题已解决的证据。** 页面不自动运行 AI；使用 Review Skill 时，AI 应对照具体关联 SHA 的代码、上下文和实际测试，在回复中说明问题仍存在、已修复或证据不足及理由。评论关闭和重新打开仍由人操作。

当前提交的评论栏及文件索引也显示人工关联的旧评论；点击新提交中的评论可打开对照，原始位置按钮仍访问历史依据。隐藏过滤按当前范围内原始/关联提交的可见性判断；「全部提交」中只要有一处可见关联就保留该讨论。关联到新提交未改动的文件时，使用评论栏对照，不要求该文件出现在提交 diff 中。跳过 Test 只过滤 diff 文件，不删除评论或复核依据。

「移除此关联」保留移除记录，可以重新确认正确关联，不改写原始评论或解决状态。数据兼容原 version 1，新增 followups、linkRevision 和请求去重记录；JSON 和导出 Markdown 包含原始依据及关联片段。旧 Git 对象被回收后仍可读保存的片段，但无法恢复未保存的完整上下文；改名线索失效时需手动指定路径，证据不足时不要声称已解决。

预览不写数据，取消会丢弃迟到结果。保存期间禁用重复操作和关闭，服务端校验版本及重复请求，冲突需刷新；网络结果不确定时可重试同一请求。仅关联已提交的 UTF-8 文本，新版本文件上限 2 MiB / 20000 行，确认范围最多 200 行及 100000 字符；每条评论至多保留 100 条关联记录和 200 次操作，文本匹配最多展示 20 个候选，超限明确提示。没有自动迁移全部评论或批量判定解决。
